1. Product overview
Accounting CRM is an internal system for an IP services firm in Noida, India. The firm raises invoices to foreign and Indian clients for patent matters (office action responses, filings, translations). Paralegals who do the underlying work send matter details in Word files. The CRM turns those files into proforma invoices, tracks payment, issues tax invoices after payment, organises documents in cloud storage, and records business expenses.
Core flow
Paralegal uploads Word file (Ref No + fees)
  -> CRM reads matter details from the Matter Master and creates a PROFORMA invoice (draft)
  -> Admin reviews and sends the proforma
  -> Payment received: an authorised approver marks it Received
  -> Admin gets a notification "Tax invoice due" -> Admin clicks Order
  -> TAX invoice generated, PDF saved to cloud folder, paralegal notified
  -> Paralegal places completed work documents in the same folder
  -> Proforma unpaid for 15 days: paralegal gets follow-up reminders

Other capabilities
Multi-currency (USD, INR, EUR). One invoice is always in one currency; conversion between currencies is supported.
Multiple banks (Deutsche Bank: USD, INR, EUR; ICICI: INR, USD) and gateways (PayPal, Skydo, Razorpay).
Expense tracking: vendor invoices (foreign law firms and Indian vendors) and owner-paid expenses, each with payment status.
Paralegals get a restricted portal. Owners get a quick expense entry form.

3. Theme and UI
The whole product uses a clean white and red theme: neat, airy, professional. White backgrounds, red used sparingly for primary actions and key accents.

Font: Inter (fallback system sans). Rounded corners 8px, no heavy shadows, generous white space.
Tables: sticky header, filters above, compact rows, status shown as small badges (Pending amber, Received/Paid green, Overdue dark red, Draft grey).
Desktop sidebar (admin panel): Dashboard, Clients, Matters, Invoices (Proforma, Tax), Payments, Expenses, Documents, Paralegals, Vendors, Reports, Settings.
Portal sidebar (paralegal): My Matters, My Proformas, My Invoices, Upload Word File, Documents, Notifications.
Fully responsive. The owner quick-add expense form and the Payments tracker must work well on a phone.
Dates in the UI: DD.MM.YYYY. Currency shown with symbol and code; INR uses Indian digit grouping (1,40,000.00), USD and EUR use international grouping.
Login page: white card, logo, red button. Logo uploaded in Settings.
4. Roles and permissions

The permission payments.mark_received is assignable by Admin to exactly the approvers. The "Mark as Received" button must not render for anyone without it, and the server must also enforce it.
Every permission change and every payment status change is audit-logged (who, when, old value, new value).
5. Masters and Excel import
5.1 Clients
Fields: name (unique), client_type (Foreign or Indian), country, state (for Indian clients), contact_person, email_1, email_2, phone, address, gstin (Indian clients), default_currency, notes. New clients can be added directly in the CRM at any time.
5.2 Matters (Matter Master)
One row per Ref No. The Ref No is a unique 4-digit code (e.g. 4521) stored as a string to keep leading zeros. Validate with ^\d{4}$, but make the DB column length 6 so the format can grow later.

5.3 Paralegals and Vendors
Paralegals: name, email, phone, firm. Each paralegal also has a user account (role Paralegal) for the portal.
Vendors: name, type (Foreign or Indian), country, email, GSTIN or tax ID, default currency, notes. Used by the Expenses module.
5.4 Excel import (docs/CRM_Master_Data.xlsx)
Header row is row 1 on every sheet. Import via a Filament page with a preview step (counts of new, updated, rejected rows), then commit, then a downloadable error report. Import is idempotent (upsert).

Skip fully blank rows and any row whose Ref No is 0000 (the example row).
Reject a Matters row if: Ref No is not 4 digits, Client Name does not exist, Service Type is invalid, or Paralegal does not exist (clear error message with sheet and row number).
Import Clients and Paralegals before Matters in the same run.
Read Ref No, App No and PCT No as text so nothing is converted to numbers or dates.
6. Invoice specification
6.1 Document types and numbering
Proforma Invoice (created from a Word upload or manually) and Tax Invoice (created only when Admin orders it after payment is received).
Tax invoice number format: AIP + YY + SEQ where SEQ is a zero-padded running sequence, e.g. AIP250196. Proforma format: PI + YY + SEQ. Prefix, year logic and padding are configurable in Settings (see Section 15).
Numbers are issued only on finalising (not for drafts) using a number_sequences table with a row lock inside a transaction, so two users can never get the same number. Numbers are never reused.
A tax invoice stores proforma_id; the proforma becomes status Converted.
6.2 Line items
Each invoice has items of these types: official_fee, professional_fee, translation, disbursement. In the PDF the body is grouped under bold headings (Official Fees, Professional Fees, Translation). Header and footer are always identical; only the body changes.

Each item has: sac_code (default 998213, editable per item), qty (default 1.00), rate, amount = qty x rate. Omit description lines that are empty (e.g. no Your ref).
6.3 Tax rules
Foreign client: no GST. The "Taxes/GSTIN" line in the totals block prints "-".
Indian client: GST 18% applies on Professional Fees only (rate configurable). Official fees and disbursements are not taxed by default (item flag taxable can override).
For Indian clients: if the client's state equals the company state (Uttar Pradesh) show CGST 9% + SGST 9%; otherwise show IGST 18%.
Totals: subtotal (all fee items) + disbursement + tax = Total Payable Amount.
6.4 Currency and conversion
Currencies: USD, INR, EUR. One invoice = one currency.
Sometimes a fee arrives in one currency and the client must be billed in another (e.g. USD to INR, or EUR to USD). Provide a "Convert currency" action on a draft invoice: choose target currency, enter the rate, rate date and rate source (RBI reference rate, Bank rate or Manual).
On conversion, recompute every item amount in the target currency (2 decimals, half-up) and store the original in invoice_conversions (source currency, source amount, target currency, rate, rate_date, rate_source, converted amount, user, timestamp). The original is never lost.
Phase 1: rate entered manually. Later (optional): daily rate import. Keep the rate source pluggable.
Optional toggle per invoice: print a small line "Exchange rate applied: 1 USD = X INR (date)". Default off.
6.5 Banks and gateways
Bank accounts table seeded with: Deutsche Bank (USD, INR, EUR) and ICICI Bank (INR, USD). Admin fills missing account details in Settings. Do not hardcode bank details in code or templates.
On choosing the invoice currency, auto-select the default active bank account for that currency; Admin may override.
Payment gateways: PayPal, Skydo, Razorpay. Optional on an invoice; when selected, print the gateway name and payment instructions (free text in Settings) below the bank block.
6.6 PDF layout (A4 portrait, matches the reference invoice)
Whole page inside a thin outer border. Top right, small italic: "Original Copy for Recipient".
Header row: company logo (red, uploaded in Settings) on the left; on the right a large grey title "Tax Invoice" (or "Proforma Invoice") with below it: Invoice No., Invoice Date (format "October 08, 2025"), Due Date, Payment Term (e.g. "15 Days").
Two-column block. Left (From): company name in bold caps, Address, GSTIN No., Email Id, M (mobile) and L (landline). Right (Invoice To): "Attn: <contact person>", client name, Address, Email(s) joined with " | ", Contact No.
Main table, columns: S.N | Description of Service | Country | SAC Code | Price | Unit | Total (<CUR> <symbol>), e.g. "Total (USD $)". Grey header row. Fee-type group headings, then items numbered 1, 2, 3...
Totals block right-aligned under the table: Taxes/GSTIN (shows "-" for foreign clients), Disbursement, and a shaded bold Total Payable Amount, each with the currency symbol.
Amount in Words line, bold, underlined, e.g. "USD $ One Thousand Four Hundred Twenty Only". For INR use "Rupees ... Only"; for EUR "EUR € ... Only".
Bank block titled "Pay Through Bank Transfer/Wire Transfer" (underlined): Beneficiary Name, Beneficiary Address, Bank Account/IBAN No, Bank Swift/BIC Code, Bank IFSC Code, Bank Name, Bank Address, taken from the selected bank account.
Terms and Conditions (text editable in Settings) on the left and, on the right, the signature image above "For <Company> / Authorised Signatory".
Centered bottom line in bold: "THIS IS COMPUTER GENERATED INVOICE".
6.7 Multi-page invoices
When items overflow the first page: repeat the table header row on every page; at the end of each non-final page print a "Carried Forward" row with the running subtotal; at the top of the next page print "Brought Forward" with the same value. Continuation pages carry a compact header (invoice no., page x of y).
The footer block (totals, amount in words, bank details, terms, signature, "computer generated" line) appears only on the last page. Do not use fixed-position footers; place the block in normal flow after the last item.
Page numbers "Page x of y" on every page. No item row may split across pages.
Test with 1, 8, 25 and 60 items.
6.8 Reference data (seed + test fixture)
Read from the sample tax invoice. Verify every value against company records before going live; all of it must live in Settings and bank accounts, not in code.

7. Paralegal Word upload
Paralegals (or Admin) upload a Word file. The CRM reads it, looks up each Ref No in the Matter Master, and creates a draft proforma invoice. Nothing is ever sent automatically.
Word file format (the CRM must also offer a "Download blank Word template" button). The table below is shown as plain text; in Word it is a real table.
Paralegal: Seema
Date: 27.10.26
 
Ref No | Fee Type          | Matter / Action         | Language | Amount | Currency
4521   | Official Fees     | Office Action Response  |          | 1400   | USD
4521   | Professional Fees | Office Action Response  |          | 800    | USD
4533   | Translation       | Specification Transl.   | Japanese | 650    | USD
4533   | Disbursement      | Courier                 |          | 20     | USD

Parsing and validation rules
The file contains one table with these exact header cells: Ref No, Fee Type, Matter / Action, Language, Amount, Currency. Wrong or missing headers reject the file with a clear message.
Ref No: exactly 4 digits and must exist in the Matter Master. Fee Type: only Official Fees, Professional Fees, Translation, Disbursement. Amount: number only (no symbol or comma). Currency: USD, INR or EUR. Language: only on Translation rows.
One file = one client and one currency. If Ref Nos belong to different clients, or currencies differ, reject with a warning listing the conflicts.
Paralegal identity: if the uploader is a paralegal, use that account. Otherwise read the "Paralegal:" line and match it to the Paralegals master. If both exist and differ, warn.
Validate every row and show row-wise errors. If any row is invalid, create nothing until the user fixes the file, or lets Admin choose "create from valid rows only".
App No, PCT No, Country, Our ref, Your ref, client name and address are not in the Word file; they come from the Matter Master. The Word "Matter / Action" text overrides the matter title in the description.
Store the original .docx in cloud storage and a word_uploads record (uploader, paralegal, status, parse result as JSON). Allow .docx only, max 10 MB.
On success: create a draft proforma (items grouped by fee type), notify Admin, open the review screen. Admin may edit items, convert currency, pick bank, then Send.

8.2 Marking payment received
Only users with payments.mark_received see and can use "Mark as Received". Dialog fields: received_on, amount received, currency, bank account or gateway, transaction reference, charges deducted (bank/gateway fee), notes.
Partial payments are allowed (status Partially received). The tax invoice can be ordered once the proforma is fully received.
Reverting Received to Pending is Admin only and requires a reason. All changes are audit-logged.
8.3 Ordering the tax invoice
When a proforma becomes Received, notify Admin (in-app and email): "Payment received for <proforma no> (<client>, <amount>). Tax invoice due." with an Order Tax Invoice button.
Admin clicks Order. A confirmation shows the invoice date (default today, editable) and the items (editable before confirming).
On confirm: issue the tax invoice number, link proforma_id, mark the proforma Converted, generate the PDF, run the folder service (Section 10), notify the paralegal.
8.4 Payment Tracker page

Filters: paralegal, client, status, currency, date range, "15+ days overdue". Totals row per currency. Export to Excel.
9. Notifications and scheduled jobs
The CRM sends notifications (Claude does not). Use Laravel Notifications with database + mail channels. Each notification links to the relevant record.

A scheduled command crm:daily-checks runs the date-based checks. It must be idempotent (no duplicate notifications for the same event on the same day).
10. Cloud storage and folder automation
10.1 Folder structure
/Paralegals/
  Seema/                      <- paralegal folder, created ONCE
    1101/                     <- Ref No folder, created only if it does not exist
      01.01.26/               <- date folder = TAX INVOICE date (DD.MM.YY)
        AIP260001.pdf         <- tax invoice, placed by the CRM
        (paralegal uploads completed work documents here)
/Proformas/<Paralegal>/<ProformaNo>.pdf     <- proforma PDFs
/Uploads/Word/<YYYY-MM>/<file>.docx        <- original Word uploads
/Expenses/<YYYY-MM>/<file>                 <- vendor invoices and owner bills

10.2 FolderService::ensureForTaxInvoice(invoice)
For each Ref No on the invoice, find the matter's paralegal.
Ensure the paralegal folder exists; create if missing (one-time).
Ensure the Ref No folder exists inside it; create only if it does not exist.
Create the date folder named with the tax invoice date as DD.MM.YY inside the Ref No folder (reuse if it already exists, e.g. two invoices on the same day).
Save the tax invoice PDF in that date folder. Record the folder in storage_folders and the file in documents.
If an invoice contains several Ref Nos, place a copy of the PDF in each Ref No folder (and under each paralegal involved).
Notify the paralegal on the tax invoice date: invoice number, date, folder link, and a reminder to upload completed work.
10.3 Paralegal access
Paralegals upload work documents through the portal into their own date folders. They can see only folders of their own matters.
Allowed types: pdf, docx, xlsx, jpg, png, zip. Max 25 MB. Files are private; use temporary signed URLs for download.
Optional setting (default off): also share the Drive folder with the paralegal's Google account.
The disk is configured in .env so the same code works with Google Drive, S3-compatible storage or local disk.
11. Expenses module
Two expense types share one table and one list page, with a type filter.
11.1 Vendor invoice expense (foreign law firm or Indian vendor)
Admin uploads the vendor's PDF invoice. A queued job sends the PDF to the Anthropic API and asks for JSON: vendor name, invoice no, invoice date, due date, currency, amount, tax amount, description, any Ref No found.
The extracted values pre-fill a review form. Admin checks and confirms. Never auto-save extracted data. Manual entry must always work too.
Match the vendor to the Vendors master (offer to create a new vendor if none matches).
Fields: vendor, vendor invoice no, invoice date, due date, currency, amount, optional GST amount (Indian vendors), optional Ref No (for matter-wise cost), category, PDF.
Status: Unpaid or Paid. When paid: paid_on, amount paid, paid from (bank account, gateway or card label), transaction reference.
Foreign vendor payments (optional section): requires_15ca_cb flag, form status, TDS applicable, TDS amount.
11.2 Owner expense (credit card, personal money or cash)
Owners use a quick-add form (30 seconds, mobile friendly): date, amount, currency, category (Travel, Software, Courier, Government fees, Office, Other), paid_by (Owner credit card, Owner personal, Cash), card label, optional Ref No, bill photo or PDF, note.
Card label only (e.g. "HDFC CC"). Never store card numbers.
Reimbursement status: Pending, Reimbursed, Not reimbursable. Marking Reimbursed records the date and bank reference.
Owners see only their own entries. Admin sees all.
11.3 Paid-by values

11.4 Reports
Unpaid vendor invoices (with due dates and overdue highlight).
Total owed to owners (pending reimbursement), per owner.
Matter-wise: revenue invoiced vs vendor cost by Ref No.
Expenses by category and month.

Create migrations with foreign keys and indexes. Every table has created_at and updated_at. Soft-delete masters; never hard-delete issued invoices.
